## 1. 产品定位

### 1.1 是什么

AWS SES 批量邮件管理平台：模板管理 + 受众管理 + 批量/定时发送 + 回执统计 + 退订闭环，带 Web 管理面板。

### 1.2 本次重写是什么、不是什么

| | 说明 |
|---|------|
| 是 | 用 Go **忠实重写**现有全部功能：API 契约、数据库、前端交互**零变化** |
| 不是 | 不新增功能、不改 API、不做多渠道（多渠道与开源化是第二步，另案） |
| 唯一预留 | 发信动作收敛到 `MailProvider` 接口之后（仅 SES 一个实现）——为第二步多渠道免重构 |

### 1.3 干系方

| 干系方 | 与系统的关系 |
|--------|-------------|
| 发信用户 | 平台操作者（营销/运营），全部日常功能的使用者 |
| 管理员 | 平台维护者：账户/渠道/系统管理 |
| 收件人 | 外部陌生人，无账号，仅通过邮件内链接与系统交互（退订） |
| 上游服务 | AWS SES（发信/回执）、SNS+SQS（事件传输）、Bedrock/OpenAI 兼容（AI 可选功能） |

## 4. 功能需求（6 组 29 条）

> 优先级说明：本重写全部为 **P0=重写必须对等**；标注 ★ 的为现网已有的可选能力（未配置时隐藏/降级），对等重写保留同样行为。

### A. 账户与访问（account）

| # | 需求 | 验收标准（=现网行为） |
|---|------|---------------------|
| A1 | 登录/登出 | 用户名+密码 → JWT（HS256，恰 `sub`+`exp` 两个 claim，24h 有效）；响应含 `access_token`、`token_type:"bearer"`、`user` 对象（含 `daily_send_limit`，空值回退 1000）。错密码 401「用户名或密码错误」；禁用账户 403「账户已被禁用」 |
| A2 | 登录限速 | 同 IP 5 分钟内 5 次失败 → 锁 10 分钟（锁定期 429「登录失败次数过多，请 N 分钟后再试」，且不跑密码哈希）；第 5 次失败当次即提示已锁定；成功登录清零。真实 IP 取 X-Forwarded-For 最后一跳（ALB 追加值） |
| A3 | 用户管理 | 管理员 CRUD。字段：username（唯一，重复建 400「用户名已存在」）/display_name/password/email（发信邮箱）/contact_email（收件邮箱）/is_admin/is_active/daily_send_limit/sender_name（≤255，超长 422）。改不存在的用户 404「用户不存在」 |
| A4 | 个人设置 | ① 收件邮箱更新（空值 400「收件邮箱不能为空」）② 退订页自定义配置的读写（任意 JSON 原样存取，空/损坏回退 `{}`）③ 退订页默认配置查询（标题/副标题/5 个默认中文原因/主题色默认 `#667eea`/按钮文案） |
| A5 | 配额执行 | 每日配额 = `daily_send_limit or 1000`；当日已发 = 该用户全部批次 `total_contacts` 之和（含退订跳过者），按 UTC 零点切日。建单时：已用尽 429「今日发送配额已用完（限额 X 封），请明天再试」；客群人数超剩余 429（文案含三个插值数字）。看板/接口可查 `daily_remaining` |

### B. 受众管理（contact）

| # | 需求 | 验收标准 |
|---|------|---------|
| B1 | 客群 CRUD | 名称/描述，归属用户（他人客群不可见不可操作，404「客群不存在或无权操作」）；删除级联删联系人；列表带每群联系人计数，搜索 name/description |
| B2 | 联系人 CRUD | 邮箱/姓名/自定义属性（JSON 字符串，如 `{"city":"上海"}`，模板变量可引用）；搜索（name OR email 模糊）；分页 `id desc`；删除需校验所属客群归属 |
| B3 | Excel 导入导出★ | 导入：首两列固定 姓名/邮箱，第 3 列起为自定义属性列名；空邮箱行跳过；无格式校验（忠实现状）；解析失败 400「文件解析失败: ...」。导出：全部联系人+其出现过的属性列（首次出现顺序）。空白模板下载：表头 姓名/邮箱/company/city。下载走 query 参数 JWT 鉴权 |
| B4 | 建单去重 | 同客群内相同邮箱只发一封（保留首个） |

### C. 模板管理（template）

| # | 需求 | 验收标准 |
|---|------|---------|
| C1 | 模板 CRUD | 名称（空 400）/主题/HTML/文本。创建与 SES v2 模板双写（`ses_name = u{uid}_{8hex}`，SES 失败 500「SES 模版创建失败: ...」）；删除时 SES 侧失败静默（仅删本地）；响应为 `{message:"模版「X」创建成功"}` 等文案体。admin 命名空间的 `/admin/templates*` 行为与用户版等价（按 admin 本人隔离——现状照抄） |
| C2 | 附件★ | 每模板 ≤5 个（超出 400）、单文件 ≤10MB；存本地 `uploads/attachments/{tpl_id}/{12hex}{ext}`；发送时以原始字节附上（BASE64 传输编码） |
| C3 | 图片上传★ | jpeg/png/gif/webp/svg，≤5MB（超限/非法类型 400）；文件名 `{16hex}{ext}`；存储模式由系统设置决定：S3（公共读，返回公网 URL）或本地（`/uploads/...`） |
| C4 | AI 优化★ | 三端点：优化建议+成品 / 八维评测（并发多模型）/ 单维修复。Provider 由系统设置决定（Bedrock IAM/AKSK/APIKey 三模式 或 OpenAI 兼容端点），**未配置时调用返回 400「未配置 AI 模型...」**；模型列表由管理员配置，普通用户可选 |

### D. 发信营销（campaign）

| # | 需求 | 验收标准 |
|---|------|---------|
| D1 | 批量发送 | `POST /send-bulk`（请求体 PascalCase `{TemplateId,GroupId}`——契约照抄）；选模板+客群 → 校验归属（404）→ 立即返回批次号与统计（total/active/skipped_unsubscribed），发送异步进行 |
| D2 | 建单四过滤 | 顺序固定：① 退订过滤（按退订对，命中者明细直接标 `Unsubscribed`，不真发）→ ② 同邮箱去重 → ③ 黑名单拦截（发送瞬间内存 Set 判定，标 `Failed`，理由 `[Blacklisted] 邮箱在黑名单中`）→ ④ 配额校验（见 A5） |
| D3 | 定时任务 | once/daily/weekly/monthly 四型；到点自动建批次。下次执行时间计算（全 UTC）：daily=当日 `hh:mm`（已过则+1天）；weekly=指定 weekday（周一=0，未指定按 0），已过则+7天；monthly=指定日（0/空按 1 号，超月末 clamp 到月末，2月兜底 28）；once=到点后 completed。可 暂停/恢复/删除；每次执行记录 last_batch_id/错误信息 |
| D4 | 批次指标 | 按批次 SQL 聚合：send（成功数）/delivery/bounce/reject/complaint/open/click 计数 + delivery_rate、open_rate（分母=delivery）、bounce_rate（分母=send，均 1 位小数）。**无回执数据时返回 `receipt_available:false`**（前端显示提示条而非 0%） |
| D5 | 邮件明细 | 全字段查询（批次/收件人/发送状态/回执状态筛选），非管理员只能看自己批次；Excel 导出（14 列中文表头，上限 10000 行） |
| D6 | 测试邮件★ | 管理员选发件身份即时单发；发件人名按身份反查用户；带配置集（batch_id 标签=test）使测试信也进回执链路 |
| D7 | 退订管理 | 列表（管理员看全部/用户按自己发件邮箱过滤）；单条恢复（文案「已恢复，该邮箱将重新接收邮件」，非本人记录 403）+ 批量恢复 |
| D8 | 用户数据看板 | 一次查询返回：summary（今日/本月/累计发送数、成功/失败批次数、配额与剩余）、delivery 聚合（送达/退信/打开/点击/投诉计数 + `receipt_available` 标志）、近 7 天发送趋势（`MM-DD` 键）、最近 5 条批次。口径=UTC 日界、配额含退订跳过者 |
| D9 | 管理员全局视图 | ① 全用户发送统计（每人批次数/联系人总数/成功失败数/首末发送时间 + 全局 success_rate=**job 数级**比率，用户按量降序）② 全部批次分页列表（含用户名/显示名）③ 各用户今日已发字典 `{uid: 数量}` ④ SES 账号配额查询（最大速率/24h 限额/已发，异常回退默认值） |

### E. 发送引擎（delivery）

| # | 需求 | 验收标准 |
|---|------|---------|
| E1 | 异步引擎 | 建单只写库（status=queued），引擎独立扫描消费：每 5 秒一轮、每轮最多 5 个批次；内存队列容量 = 并发×速率×4，队满本轮中止（批次留待下轮）；Worker 池并发默认 2 可配；每 Worker 每秒限速，速率 0=自动 `floor(SES启动配额快照/并发)` 下限 1；可选固定窗口总量限制 |
| E2 | 事件回写 | SQS 长轮询（10条/20s）消费 SNS 包装的 SES 事件，7 类：SEND/DELIVERY/BOUNCE/COMPLAINT/OPEN/CLICK/REJECT（统一大写比较）。按 `message_id` 匹配明细（查不到忽略）；**Pending 明细收到任意事件先改 Success**；OPEN/CLICK 计数累加+首次时间；BOUNCE 落类型/子类型/诊断码；DELIVERY 落送达时间（解析失败用当前时间）。**幂等语义=现状**：SQS at-least-once 投递下，重复的 OPEN/CLICK 事件会重复累加计数（open_count 虚增，登记毛边#9，第二步再议去重）；状态类字段为覆盖写、天然幂等。毒消息：同消息失败 ≥3 次删除，否则留队重投（DB 闪断自愈不丢事件） |
| E3 | 断点恢复 | 明细状态机：`Pending→Success/Failed/Unsubscribed`。发送前复查明细仍为 Pending（防重复发送）；批次状态机：`queued→sending→success/partial/failed`；扫描时自愈：已收到回执但状态仍 Pending 的明细修正为 Success；真 Pending 数为 0 时按失败占比判定终态（全败=failed、部分=partial 文案「N 封发送失败」、全成=success）。进程重启后从 DB 状态自然续作（不重发已终态明细） |
| E4 | 退订闭环 | 邮件正文含退订链接（`{UNSUBSCRIBE_BASE_URL}/unsubscribe?token=`，未配置时变量替换为 `#`）+ 邮件头 `List-Unsubscribe`/`List-Unsubscribe-Post: One-Click`（仅配置了 BASE_URL 时）。Token：`email|source` 的 HMAC-SHA256 hex 签名**截前 16 字符**，整串 `email|source|sig` 做**带 padding 的 URL-safe base64**；验证恒时比较、无过期、split 恰 3 段。GET 渲染退订页（标题/原因列表来自配置，已退订显示 Already Unsubscribed 页）；POST 支持 one-click（RFC 8058，token 取 query 或 form，原因默认 one-click 截 64 字符）；写入按退订对幂等；成功响应**纯文本 "ok"** |

### F. 系统管理（system）

| # | 需求 | 验收标准 |
|---|------|---------|
| F1 | 渠道配置★ | 发信相关环境变量：区域/配置集/SQS 队列/退订基址/引擎参数（并发/速率/窗口）；凭据（SECRET_KEY/DATABASE_URL）经 SSM 注入不落盘。（重写版此层收敛到 MailProvider 接口后，但对外行为不变） |

| F5 | 运维工具★ | 日志尾部查看/下载（app.log）；SQL 控制台（默认仅 SELECT/SHOW/DESCRIBE/EXPLAIN，`allow_write` 放开写；结果 `{columns,rows,row_count}`） |
| F6 | SSO | **范围外不实现**（见第 8 节）；但需**显式注册占位路由**使 `/sso/*` 6 端点返回与现网一致的 404 JSON `{"detail":"Not Found"}`（gin 默认 404 形状不同，必须显式对齐）；`sso_*` 设置键保留兼容 |

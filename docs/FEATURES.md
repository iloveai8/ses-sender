## 1. 发邮件全链路（两条泳道 + 汇合点）

### 1.1 流程图

```
   【立即发送泳道】                【定时发送泳道】
        │                              │
  批量发送页点"开始发送"         定时任务页创建（如"每天 09:00"）
        │                              │
        │                        存入 scheduled_jobs 表
        │                         （此刻没人管它，纯排队）
        │                              │
        │                      ┌─────────────────────┐
        │                      │  Scheduler 闹钟线程  │ ← 定时泳道的全部独有环节
        │                      │  每30秒醒一次：      │    就这一个方框
        │                      │  有人到点了吗？       │
        │                      └────────┬────────────┘
        │                            到点 │
        ▼                               ▼
        └────────────► 汇合点：send_bulk_email() ◄────────────┘
                        （建批次，从此两条路再无区别）
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   读模板+客群          退订过滤+去重          建批次写库(queued)
                                                    │
                                                    ▼
                                     Sender 引擎（Scanner + Worker×2）
                                      渲染 → 调 SES → 发出
                                                    │
                                                    ▼
                                     AWS SES 投递 → 收件人
                                                    │
                                                    ▼
                                     SQS Worker 拉回执 → 写库
                                                    │
                                                    ▼
                                     页面三处指标显示
```

> 测试邮件是第三条小道：不进汇合点，直接单发 SES、不带批次（发件人名/配置集仍生效）。
> 退订支线：收件人点退订 → HMAC 验签 → 写 `unsubscribe_list` → **下次建单时被过滤**，形成闭环。

### 1.2 角色分工表（谁停了会怎样）

| 角色 | 位置 | 干什么 | 停了会怎样 |
|------|------|--------|-----------|
| API | 主进程 | 接页面请求、建批次 | 页面全挂 |
| Scheduler | 后台线程 | 定时任务到点时替用户"按发送键"，仅此一事 | **定时邮件静默不发**；立即发送不受影响 |
| Scanner | 引擎线程 | 每秒把 queued 批次搬进发送队列 | 批次永远 queued，一封不发 |
| Worker×2 | 引擎线程 | 渲染+调 SES 发送，速率受控 | 发送停滞/变慢 |
| SQS Worker | 后台线程 | 拉送达/打开事件回写库 | 邮件照发，但指标全 0 |

### 1.3 建单时的过滤规则（顺序）

1. **退订过滤**：按 `(收件邮箱, 发件邮箱)` 二元组查 `unsubscribe_list` → 命中者明细行直接标 `Unsubscribed`（拦截，不会真发）
2. **同邮箱去重**：客群内同邮箱只发一封
3. **黑名单**：发送瞬间 Worker 内存 Set 二次拦截（标 `Failed`，理由 `[Blacklisted]`）
4. **每日配额**：超 `daily_send_limit` 拒绝建单（429）

## 2. 发件人名称（sender_name）

## 1. 发件人名称（sender_name）

### 1.1 定义

每个账户可绑定一个**发件人名称**——收件人邮件客户端里显示的 `发件人` 名字。绑定后**所有发信场景统一使用**，无需在发送时手动填写。

### 1.2 名称解析规则（优先级从高到低）

```
用户管理里填的 sender_name  →  发件邮箱的 @ 前缀（如 chenhu@xx.com → chenhu）
```

- 留空 = 用邮箱前缀兜底，页面上的兜底值以灰色显示
- 括号格式：`"名称" <邮箱>`（如 `"Jackpotland Casino" <gamenews@jackpotlandcasino.com>`）

### 1.3 生效场景（后端三处）

| 场景 | 实现位置 | 说明 |
|------|---------|------|
| 批量发送（含定时任务） | `domain/sending/service.py` `send_bulk_email()` + `core/sender.py` Scanner | 批次创建时快照 `from_name` 存入 `sending_jobs`，Worker 发送时使用（**同一批次内改名不影响已入队任务**） |
| 测试邮件 | `domain/sending/service.py` `send_test_email()` | 按所选发件邮箱反查用户，取其 sender_name |
| 前端预览 | admin 测试邮件页 | 与后端解析逻辑一致（按邮箱匹配用户取 sender_name，兜底前缀） |

### 1.4 存储结构

| 表 | 字段 | 用途 |
|----|------|------|
| `users` | `sender_name varchar(255) NULL` | 账户级配置（源头），用户管理增/改时写入 |
| `sending_jobs` | `from_name varchar(255) NULL` | 批次级快照，发送时定格，保证历史批次可追溯 |

迁移文件：`d1e2f3a4b5c6`（sending_jobs.from_name）、`e3f4a5b6c7d7`（users.sender_name）。

### 1.5 前端展示位置

| 页面 | 位置 |
|------|------|
| admin → 用户管理 | 表格「发件人名称」列（兜底灰色前缀）；新建/编辑表单输入框 |
| admin → 发送统计 | 用户统计表「发件人」列（接口字段 `sender_name`） |
| admin → 测试邮件 | 选身份后「发件人将为：xxx（用户管理可自定义）」 |
| 用户 → 批量发送 / 定时发送 | 顶部信息条「发送邮箱 \| 发件人」 |

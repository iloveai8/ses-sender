## P0-3 域名 + HTTPS（消灭明文传输）🔴

- **现状证据**：全站 HTTP，登录密码/token 明文过网；公共 WiFi 可被嗅探；
  退订链接印着 AWS 长域名（可信度差）
- **整改操作**（域名拿到后，Claude 全程接手）：
  ```
  ① 你：搞域名（推荐公司主域要个子域 ses.xxx.com；或 Route53 注册）
  ② Claude：Route53 区 + A(ALIAS) 指向 ALB
  ③ Claude：ACM 申请免费证书（DNS 验证）→ ALB 加 443 监听器绑证书
  ④ Claude：:80 默认动作改 301 跳 https（顺带 host-header 门禁，扫描器被拒）
  ⑤ Claude：任务定义 UNSUBSCRIBE_BASE_URL 切 https://域名 → 发版
  ```
- **验收**：`https://域名` 可访问且证书有效；`http://` 自动跳 https；
  裸 ALB 地址访问被拒/跳转 🔍
- **状态**：✅ **2026-09-11 完成**
  - 域名：`ses-sender.luckystargame.com`（CNAME→ALB；复用现成 ACM 通配符证书 `*.luckystargame.com`）
  - 终态架构：`:443` = 证书+全部分流规则（2 路径→后端，默认→前端）；`:80` = 纯 301 跳 https（唯一规则）
  - 实测：https 页面 200 / http 全路径 301 / 退订走线通 / https 登录全链路 200 /
    退订域名已切 `https://ses-sender.luckystargame.com`（运行任务环境变量核验）
  - 踩坑实录：ACM 证书**分区域**（申错区则 ALB 下拉看不见，须与 ALB 同在 us-east-2）；
    :80 的路径规则优先于默认重定向规则——留着她 http 明文请求会绕过 301，
    终态应把 :80 的路径规则删光只留 301

## P1-4 登录接口暴力破解防护 🟠

- **现状**：/api/auth/login 无限速，可无限次试密码
- **缓解现状**：强密码（P0-1 后）已大幅降低风险；公网无法直达后端 API（必经前端代理）
- **根治选项**（选其一，均不动代码）：
  - A. ALB 挂 AWS WAF：Rate-based 规则（同 IP 5 分钟>100 次 /api/* 请求则封）≈$5/月+规则费
  - B. 等下次改代码顺路加接口限速（记录在案）
- **建议**：暂靠强密码；域名+HTTPS 落地后评估 WAF
- **状态**：✅ **2026-09-14 完成（方案 B 代码限速，$0）**
  - `core/ratelimit.py`：同 IP 5 分钟窗口内失败 5 次 → 锁 10 分钟（429，锁定期不跑密码哈希）；
    成功登录清零；滑动窗口（旧失败自动滑出）；触发锁定时顺带清理过期条目防内存膨胀
  - 真实 IP 取 `X-Forwarded-For` **最后一项**（ALB 追加的可信值；最左可伪造不能取——
    后端直连看到的是前端容器 IP，不处理会把所有用户算成一个）
  - 单测 6 条（窗口滑动/锁定/清零/IP 解析）+ 全量回归 50 过
  - 边界：进程内存实现，当前单实例足够；将来 api 多实例需换 Redis（届时引入）
